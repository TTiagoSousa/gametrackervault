# 04 · Backend structure

NestJS 11, TypeScript, Prisma 7. Entry point `src/main.ts`, module root
`src/app.module.ts`.

## Tree

The backend is the `@gametracker/backend` workspace of the monorepo:

`ROLES` and the `Role` type from `@gametracker/shared` are the copy the frontend can
import; the source of truth for the database is the `Role` enum in the Prisma schema.
The backend uses the enum generated by Prisma.

## Anatomy of a module

Domain modules follow this shape (`user/` is the living example; `library/` is the
first user-data module to follow it):

```
<domain>/
├── <domain>.module.ts             declares controller, service and repository
├── <domain>.controller.ts         routes + guards + DTOs
├── <domain>.service.ts            thin shell: delegates to helpers
├── dto/
│   ├── create-<x>.dto.ts          class-validator
│   └── update-<x>.dto.ts          PartialType(Create…)
├── helpers/
│   ├── create<X>.ts               one exported function per file
│   ├── find<X>.ts
│   ├── findAll<X>.ts
│   ├── update<X>.ts
│   └── delete<X>.ts
└── repositories/
    ├── <x>-repository.ts          interface + helper types
    └── prisma/
        └── prisma-<x>-repository.ts   @Injectable() that implements it
```

## The contract of each layer

### Controller
It only does three things: apply guards, extract `req.user.id`, call the service.

```ts
@Controller('user')
@UseGuards(JwtAuthGuard)
export class UserController {
  constructor(private readonly userService: UserService) {}

  @Get('me')
  findCurrent(@Req() req: Request & { user: JwtPayload }) {
    return this.userService.findCurrent(req.user.id);
  }
}
```

Literal routes before parametric ones: a future `@Patch('reorder')` **must come before**
`@Patch(':id')`, otherwise Nest treats `reorder` as an id. `GamesController` already
depends on this: `@Get(':id')` is declared after `search` and `filters`, and
`LibraryController` declares `stats` and `discover` before `@Get(':gameId')`. Numeric ids
come in through `ParseIntPipe` (`@Param('id', ParseIntPipe)`), which returns 400 for a
value that isn't an integer.

### Service
No logic. Receives repositories by injection and passes them to the helper.

```ts
@Injectable()
export class UserService {
  constructor(private readonly userRepository: PrismaUserRepository) {}

  async create(dto: AdminCreateUserDto) {
    return createUserByAdmin(dto, this.userRepository);
  }
}
```

### Helper
One exported function, everything via arguments, stateless. This is where business
validations and Nest HTTP exceptions live.

```ts
export async function createUserByAdmin(
  dto: AdminCreateUserDto,
  userRepository: PrismaUserRepository,
) {
  const usernameExists = await userRepository.findByUsername(dto.username);
  if (usernameExists) throw new ConflictException('Username já existe');
  …
}
```

Helpers compose with each other: `registerFirstUser` (in `auth/`) calls `createUser` (in
`user/`).

### Repository
Interface first (`user-repository.ts`), Prisma implementation second
(`prisma/prisma-user-repository.ts`). Only the repository touches `PrismaService`.

### Modules that talk to an external API
`games/` has no database nor repository: in place of the repository there's an
`@Injectable()` HTTP client (`igdb/igdb.client.ts`) that the service receives by
injection and passes to the helpers, exactly as it would pass a repository. The client
concentrates what belongs to the external service — authentication, rate limiting, HTTP
errors — and the helpers keep the logic (building the query, mapping the response). Pure
helpers (no I/O), such as `buildSearchQuery`, have Jest tests next to them
(`<helper>.spec.ts`).

`ai/` talks to the Anthropic API through `anthropic/anthropic.client.ts`, which isn't a
provider: it's two exported functions (`listModels(apiKey)` and `streamMessage(args)`)
that the helpers call directly, because the key belongs to each user and arrives as an
argument. It uses raw `fetch` (no SDK), parses the SSE stream by hand and translates
Anthropic's HTTP errors into Nest exceptions with messages in Portuguese.

### Streaming responses
A route that returns in chunks (`POST /ai/chat`) uses `@Res()` and writes the response
itself: `application/x-ndjson` headers, `Cache-Control: no-cache, no-transform` and
`X-Accel-Buffering: no`, `flushHeaders()` on the first event and one JSON line per
event. The helper receives an `emit(event)` function and an `AbortSignal` (the
controller aborts it on the response's `close`), and knows nothing about HTTP. Since
with `@Res()` Nest no longer handles exceptions, the controller catches them: before the
first event it responds with the normal HTTP error (`{ statusCode, message }`), after
that it writes a `{ type: 'error' }` line.

### Services shared between modules
When a module needs data from another, the other exports a small service and the first
imports the module: `IntegrationsModule` exports `IntegrationCredentialsService` and
`GamesModule` does `imports: [IntegrationsModule]`. Since Nest providers are singletons
per module, that service's cache and invalidation are the same for both sides.

The same between `games/` and `library/`: `GamesModule` exports `GamesService` and
`LibraryModule` imports it; `LibraryService` receives it by injection and passes it to
the `saveLibraryEntry` helper as it would a repository (that's where the game summary
comes from — `games.summary(id)` — for the `Game` table), to `getLibraryStats`
(`games.facts(ids)`, genres and average times) and to the random game
(`games.random(exclude)`). This way `library/` never talks to IGDB directly.

`LibraryModule` also exports `PrismaLibraryRepository`: `AiModule` imports
`LibraryModule` and `GamesModule` to read the user's shelf (for the assistant's
instructions) and run the tools against IGDB. `AuthModule` uses the
`PrismaUserRepository` that `UserModule` exports — on login and, since the session is
confirmed against the database, in `JwtStrategy`.

## Cross-cutting patterns

### Validation
`main.ts` installs a global `ValidationPipe` with `transform: true` and
`whitelist: true` — fields not declared in the DTO are silently stripped from the
request body.

DTOs use `class-validator`. An `Update…Dto` should be `PartialType(Create…Dto)` from
`@nestjs/mapped-types` (already a dependency).

### Ordering with an integer `order`
Not used yet, but it's the pattern for reorderable lists: create → `order = count(...)`;
delete → close the gap; reorder → validate that the received list has the same ids as
what exists and apply in a `$transaction`.

## Bootstrap (`main.ts`)

```ts
app.set('trust proxy', 'loopback');
app.use(cookieParser());
app.useGlobalPipes(new ValidationPipe({ transform: true, whitelist: true }));
app.enableCors({ origin: process.env.FRONTEND_URL, credentials: true });
app.enableShutdownHooks();
await app.listen(process.env.PORT ?? 3000, process.env.HOST ?? '0.0.0.0');
```

- `trust proxy: 'loopback'` makes `req.secure` reflect Nginx Proxy Manager's https (via
  the local nginx), and that's what decides the `secure` cookie.
- `enableShutdownHooks()` because systemd stops the service with SIGTERM — without it
  Nest doesn't close the Postgres connections.
- No global prefix — routes live at the root (`/auth/login`, not `/api/auth/login`). In
  production `/api` belongs to nginx, which strips it before forwarding.
- `credentials: true` in CORS is mandatory: without it the session cookie doesn't travel.

## Creating a new module

1. `src/<domain>/` with the tree above.
2. Model in `schema.prisma` + generated migration (see [03](./03-data-model.md)).
3. Repository interface first, Prisma implementation second.
4. One helper per operation, receiving the repositories as arguments.
5. A service that only delegates; a controller that only routes, with `JwtAuthGuard`.
6. Register the module in `app.module.ts`.
7. If another module needs the repository, `exports: [PrismaXRepository]` (as
   `UserModule` does for `AuthModule`), or a service, `exports: [XService]` (as
   `IntegrationsModule` does for `GamesModule` and `GamesModule` for `LibraryModule`).
8. New routes mirrored in `apps/frontend/src/Service/endPoints.ts` and documented in
   [06](./06-api-endpoints.md).
